Proyecto:
Prototipo RAG para tesis

Ruta local:
/home/diego/rag-tesis

Repositorio:
https://github.com/diegoarcecast/RAG.git

Objetivo del sistema:
Este sistema permite cargar documentos académicos y técnicos, extraer texto, dividirlo en chunks, generar embeddings, almacenarlos en PostgreSQL con pgvector, recuperar evidencia documental mediante búsqueda semántica, generar respuestas con un modelo local y consultar el sistema desde terminal o Discord.

============================================================

1. FLUJO GENERAL DEL SISTEMA
   ============================================================

El flujo completo del sistema es:

1. Colocar documentos en la carpeta local del corpus.
2. Ejecutar ingesta documental.
3. Guardar documentos y chunks en PostgreSQL.
4. Generar embeddings para los chunks nuevos.
5. Verificar que no existan chunks sin embedding.
6. Ejecutar consultas RAG desde terminal o Discord.
7. Registrar trazabilidad en rag_queries y retrieval_logs.
8. Revisar respuesta, documentos recuperados, chunks, similarity_score, distance y evidencia.
9. Usar la salida completa para evaluación académica o la salida compacta para Discord.

Flujo técnico resumido:

Documento
-> extracción de texto
-> limpieza
-> chunking
-> documents / document_chunks
-> embeddings con nomic-embed-text
-> pgvector
-> búsqueda semántica
-> generación con gemma4:e4b
-> respuesta
-> trazabilidad
-> Discord o terminal

5. CARGAR UN DOCUMENTO INDIVIDUAL
=================================

Comando recomendado para documento real:

python -m app.ingest_document data/raw/samples/nuevo_documento.pdf --chunk-size 1200 --chunk-overlap 200 --min-chunk-size 120 --save-db

Explicación:

python -m app.ingest_document
Ejecuta el comando de ingesta individual.

data/raw/samples/nuevo_documento.pdf
Ruta del documento que se desea cargar.

--chunk-size 1200
Define el tamaño aproximado de cada chunk en caracteres.

--chunk-overlap 200
Define cuántos caracteres se repiten entre chunks consecutivos para no perder contexto.

--min-chunk-size 120
Evita guardar chunks demasiado pequeños.

--save-db
Guarda el documento y sus chunks en PostgreSQL.

Glosario:

--chunk-size
Tamaño máximo aproximado del fragmento documental.

--chunk-overlap
Solapamiento entre fragmentos para preservar continuidad.

--min-chunk-size
Tamaño mínimo aceptado para guardar un chunk.

--save-db
Indica que el resultado debe persistirse en la base de datos.

Seguridad:
Modifica la base de datos porque inserta registros en documents y document_chunks. No borra información existente.

8. VERIFICAR CONTEOS DE CHUNKS Y EMBEDDINGS
===========================================

Comandos:

psql -h localhost -U rag_user -d rag_tesis -P pager=off -c "SELECT COUNT(*) AS total_chunks FROM document_chunks;"

psql -h localhost -U rag_user -d rag_tesis -P pager=off -c "SELECT COUNT(*) AS chunks_con_embedding FROM document_chunks WHERE embedding IS NOT NULL;"

psql -h localhost -U rag_user -d rag_tesis -P pager=off -c "SELECT COUNT(*) AS chunks_sin_embedding FROM document_chunks WHERE embedding IS NULL;"

Explicación:

Primer comando:
Cuenta todos los chunks existentes.

Segundo comando:
Cuenta los chunks que ya tienen embedding.

Tercer comando:
Cuenta los chunks que todavía no tienen embedding.

Glosario:

psql
Cliente de PostgreSQL desde terminal.

-h localhost
Indica que PostgreSQL está en la máquina local.

-U rag_user
Usa el usuario rag_user.

-d rag_tesis
Usa la base de datos rag_tesis.

-P pager=off
Evita que PostgreSQL abra el paginador.

-c
Ejecuta una consulta SQL directa desde terminal.

IS NOT NULL
Filtra registros donde el campo tiene valor.

IS NULL
Filtra registros donde el campo está vacío.

Seguridad:
Seguro. Solo consulta información. No modifica datos.

14. LIMPIAR UNA INGESTA POR FILE_PATH
=====================================

Usar solo si se cargó un documento por error.

Comando:

python - <<'PY'
from app.ingestion.repository import delete_document_by_file_path

file_path = "/home/diego/rag-tesis/data/raw/samples/nuevo_documento.pdf"

deleted = delete_document_by_file_path(file_path)

print(f"Documentos eliminados: {deleted}")
PY

Explicación:

delete_document_by_file_path
Busca documentos en la tabla documents por su ruta file_path y los elimina.

ON DELETE CASCADE
Al eliminar el documento, PostgreSQL elimina automáticamente sus chunks asociados en document_chunks.

Riesgo:
Alto si se coloca mal el file_path. Puede eliminar documentos y chunks cargados en la base de datos.

Regla:
Verificar muy bien el file_path antes de ejecutar.
